# 轻量级文档检索工具设计说明

本文以一个虚构的本地文档检索工具为例，说明设计目标、处理流程和结果展示方式。工具面向个人知识库，在本地完成 Markdown 文件的读取与检索。

## 设计目标 Design Goals

- **快速定位**：通过关键词找到相关文档，并显示命中段落。
- **保留上下文**：结果中包含文档标题、所在章节和原始路径。
- **便于维护**：索引与源文件分开存储，文件更新后可以重新构建。

## 处理流程 Workflow

1. 读取指定目录中的 Markdown 文件，跳过临时文件和缓存目录。
2. 按标题与段落切分内容，记录每个片段在原文中的位置。
3. 接收查询词，返回匹配的片段，并提供打开原文的入口。

### 索引构建 Indexing

每条索引记录包含 `title`、`section`、`path` 和 `text` 四个字段。展示时优先使用文档标题，缺少标题时使用文件名。

#### 段落切分 Paragraph Splitting

按空行切分正文；代码块与表格作为完整片段保存，以保留阅读上下文。

##### 边界条件 Edge Cases

空文档跳过索引，重复路径只保留一条记录。读取失败时记录文件路径，允许继续处理其他文件。

## 示例结果 Example Results

以下数字仅用于演示表格和公式排版。

| 测试集合 | 文档数量 | 平均查询耗时 |
| --- | ---: | ---: |
| 示例集合 A | 120 | 18 ms |
| 示例集合 B | 360 | 26 ms |
| 示例集合 C | 800 | 43 ms |

设第 $i$ 次查询耗时为 $t_i$，共执行 $N$ 次查询，平均耗时记为 $\bar{t}$：

$$
\bar{t}=\frac{1}{N}\sum_{i=1}^{N}t_i
$$

## 数据记录 Data Records

下面是一条简化的索引记录：

```json
{
  "title": "接口设计说明",
  "section": "参数与返回值",
  "path": "notes/interface.md",
  "text": "查询结果包含标题、片段与文档路径。"
}
```

> 检索结果用于定位内容，完整语境应以源文档为准。
